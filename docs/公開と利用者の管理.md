# 公開と利用者の管理（管理者向けの手順書）

図面計測ツールを、**管理者が登録したメールアドレスの人だけ**が使えるように公開する手順です。
最初の設定は一度だけ（30分ほど）。あとは管理の画面でメールアドレスを登録・削除するだけです。

## しくみ

```
利用者 ──→ Cloudflare Access ──→ Cloudflare Pages（アプリ）
            │ 登録したメールの人にだけ        │ ログインの証明を確かめてから配る
            │ 6桁のコードを送る               │（証明の無い・偽物の要求は 403）
            ▼
        グループ「図面計測ツール 利用者」 ←── 管理者が /admin で登録・削除
```

- ログインは「メールに届く6桁のコード」です。パスワードは要りません。
- 登録していないメールアドレスにはコードが届かず、アプリを開けません。
- 図面と計測のデータは、これまでどおり**使う人の端末の中だけ**に保存されます。サーバーには送りません。アプリはブラウザの決まり（CSP）で、外への通信そのものができないようにしてあります。
- 削除した人は、ログイン中のセッションもすぐに切れます。電波のある所でアプリを開いた時点で「もう一度ログイン」の画面になり、使えなくなります。
- Cloudflare Zero Trust の無料プランで使えるのは **50人まで**です。それより多いときは有料プラン（1人あたり月額）になります。

## 用意するもの

- Cloudflare のアカウント（無料）：<https://dash.cloudflare.com/sign-up>
- この GitHub のリポジトリ（zumen-keisoku）
- 管理者のメールアドレス（管理の画面を使う人。複数でもよい）
- Node.js（初期設定の台本を流すため。dxf-takeoff の作業で入っているもの）

## 1. Cloudflare Pages にアプリを置く

1. Cloudflare のダッシュボード → **Workers & Pages** → **作成（Create）** → **Pages** → **Git に接続（Connect to Git）**。
2. GitHub を連携し、`zumen-keisoku` を選びます。
3. ビルドの設定：
   - フレームワーク：**なし（None）**
   - ビルドコマンド：空欄
   - ビルドの出力先：`/`（通らないときは `.`）
4. 「保存してデプロイ」。アドレスは `https://zumen-keisoku.pages.dev` になります。名前が使われていたときは、末尾に文字が付きます。その名前を、後の `--project` に使います。
5. この時点で開くと「**準備中です**」と出ます。設定が終わるまでは誰も使えないようにしてあるためで、正常です。

## 2. Zero Trust の初期設定

1. ダッシュボード → **Zero Trust** を開きます。
2. **チーム名**を決めます（例：`kobayashi-naiso`）。ログインの画面のアドレス `チーム名.cloudflareaccess.com` になります。
3. プランは **Free** を選びます。支払い方法の登録を求められることがありますが、50人までは料金はかかりません。

## 3. API トークンを2つ作る

ダッシュボード右上の人のマーク → **マイ プロフィール** → **API トークン** → **トークンを作成** → **カスタム トークン**。

| トークン | 権限（すべて「アカウント」の「編集」） | 使う所 |
|---|---|---|
| ① 初期設定用 | Access: アプリとポリシー／Access: 組織、ID プロバイダー、およびグループ／Cloudflare Pages | 手順 4 で1回だけ。**終わったら削除** |
| ② 管理の画面用 | Access: 組織、ID プロバイダー、およびグループ **だけ** | 管理の画面がずっと使う |

- 「アカウント リソース」は、この Cloudflare アカウントだけにします。
- トークンは作ったときに一度しか見えません。手順 4 が終わるまで、メモ帳などに一時的に控えます（終わったら消します）。
- **アカウント ID**（32桁の英数字）は、ダッシュボードの Workers & Pages の右側、またはアドレスバーの `dash.cloudflare.com/` の後ろにあります。

## 4. 初期設定の台本を流す

VS Code のターミナル（PowerShell）で、このフォルダから流します。トークンは、コマンドの履歴に残らないよう環境変数で渡します。

```powershell
$env:CF_SETUP_TOKEN   = "①のトークン"
$env:CF_RUNTIME_TOKEN = "②のトークン"
# まず試し（何も変えずに、予定だけ出す）
node tools/setup-cloudflare.mjs --account <アカウントID> --project zumen-keisoku --admin あなた@example.com --dry-run
# よければ本番
node tools/setup-cloudflare.mjs --account <アカウントID> --project zumen-keisoku --admin あなた@example.com
Remove-Item Env:CF_SETUP_TOKEN, Env:CF_RUNTIME_TOKEN
```

- 管理者が複数のときは `--admin a@example.com,b@example.com`。
- 独自のドメインを使うときは `--domain zumen.example.co.jp` を足します（先に Pages の「カスタム ドメイン」で設定しておきます）。
- 台本がすること：
  - ログインの方法（ワンタイムPIN）を作る
  - グループ「図面計測ツール 利用者」を作り、管理者を入れる
  - このグループの人だけを通すポリシーと Access のアプリを作る（`zumen-keisoku.pages.dev` とプレビュー用の `*.zumen-keisoku.pages.dev`）
  - Pages の環境変数を入れる
- 何度流しても、同じものを二重には作りません。
- 終わったら、①のトークンを Cloudflare で**削除**します。

## 5. 再デプロイして確かめる

1. Workers & Pages → zumen-keisoku → **デプロイ** → 最新の行の「…」→ **デプロイを再試行**。環境変数は、次のデプロイから効きます。
2. 別のブラウザ（シークレット ウィンドウ）で `https://zumen-keisoku.pages.dev` を開きます。
   - メールアドレスを聞かれる → 管理者のメールを入れる → 届いた6桁のコードを入れる → アプリが開けば成功です。
3. `https://zumen-keisoku.pages.dev/admin` を開くと、利用者の管理の画面が出ます。
4. 登録していないメールアドレスでは、アプリを開けないことを確かめます。

## 6. GitHub Pages を止める（大事）

手順 5 まで済んだら、これまでの公開先（`030809240222im-star.github.io/zumen-keisoku`）を止めます。**止めないと、そちらのアドレスから誰でも使えてしまいます。**

1. GitHub のリポジトリ → **Settings** → **Pages** → 「Unpublish site」（または Source を None）。
2. 中身（コード）も見せたくないときは、**Settings** → **General** → 一番下の **Change repository visibility** → **Private**。
   - Cloudflare Pages の GitHub 連携は、非公開のリポジトリでもそのまま動きます。
   - 非公開にすると、無料の GitHub では GitHub Pages が使えなくなります（止める目的にも合います）。

## ふだんの使い方（管理の画面 `/admin`）

- **登録**：メールアドレスを入れて「登録する」。改行やカンマで区切れば、まとめて登録できます。メモ（会社名・氏名）も付けられます。
- **招待**：「招待文」で、その人あての案内の文面をコピーし、メールやチャットで送ります。
- **削除**：「削除」で登録を外します。ログイン中のセッションもすぐに切れます。
- 管理者を増やす・減らすとき：Pages の環境変数 `ADMIN_EMAILS` を書き換えて、再デプロイします。管理の画面からは管理者を削除できません（締め出しを防ぐため）。
- 50人の枠：一度ログインした人が枠を使います。削除した人の枠は、Zero Trust → **ユーザー（Users）** で外すと空きます。

## 任意：メモ・登録日・操作の記録を残す（KV）

1. Workers & Pages → **KV** → **作成**（名前は `zumen-kv` など）。
2. Pages の zumen-keisoku → **設定** → **バインディング** → **KV 名前空間**。変数名 `ZUMEN_KV` で、1 で作った KV を選びます。
3. 再デプロイします。管理の画面にメモの欄と「最近の操作」が出ます。

## 困ったとき

| 出たもの | 理由と直し方 |
|---|---|
| 「準備中です」 | 環境変数 `ACCESS_TEAM_DOMAIN`・`ACCESS_AUD` が無い。手順 4 を流して再デプロイ |
| 「このページは登録した人だけが使えます」 | Access のアプリがこのアドレスを守っていない、またはログインできていない。Zero Trust → アクセス → アプリケーション で、アドレスを確かめる |
| `/admin` で「管理者だけが使えます」 | 環境変数 `ADMIN_EMAILS` に自分のメールが無い |
| 管理の画面で「権限が足りません」 | ②のトークンの権限、または環境変数 `CF_API_TOKEN` を確かめる |
| コードのメールが届かない | 迷惑メールのフォルダを見る。登録したメールアドレスの綴りを確かめる |
| 古い画面のまま | 一度再読み込み。ホーム画面に追加したものは、開き直す |

## 守っていること・守れないこと

- **守っていること**：
  - 登録した人だけがアプリを開ける。
  - 管理の画面は管理者だけ。
  - よそのサイトから管理の操作をさせない。
  - 図面のデータを外へ送らない（ブラウザの決まりで止める）。
  - PDF の中のスクリプトを動かさない。
  - 外部の CDN を使わない（ライブラリはアプリと同じ場所に置き、改ざん検査付き）。
- **守れないこと**：
  - 登録した人が、自分の端末で開いたアプリの中身（HTML）を保存して持ち出すことは止められません。
  - 端末を共用するときは、ログアウトの「この端末のデータを消す」を使うよう案内してください。
